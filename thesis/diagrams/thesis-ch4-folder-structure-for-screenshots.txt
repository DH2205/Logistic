================================================================================
CHAPTER 4 — How to document project structure (LogiShop / Next.js monolith)
================================================================================

The app stays ONE Next.js codebase, but the repo groups **presentation** and
**server-side modules** into top-level folders for navigation and thesis figures:

  **frontend/**  — shared React UI (`components/`, `contexts/`)
  **backend/**   — shared logic & integrations under `backend/lib/` (imported in
                    code as `@/lib/...` via `tsconfig.json` path aliases)
  **app/**       — App Router: page routes **and** `app/api` route handlers (unchanged)

Next.js still requires `app/` at the project root for routes. Use TWO FIGURES:

  Figure 4.1  =  Presentation / client UI layer
  Figure 4.2  =  Server API + shared logic + persistence scripts

Paragraph text (4.1.2 a — backend bullet):
• **app/api/** — **Controller** layer: validates requests, calls `@/lib` (physical path `backend/lib`), returns JSON.
• **backend/lib/** — **Model / service** helpers: auth, order access, UPS integration,
  scoring/routing utilities, Zod validation, etc.
• **supabase/** — **Schema** scripts and migrations for PostgreSQL.
• **scripts/** — Maintenance and thesis demo tooling (not user-facing).


--------------------------------------------------------------------------------
4.1.2 b — Core algorithm implementation (LogiShop — replace tourism scorer)
--------------------------------------------------------------------------------

Describe in prose (no code required):

• **Shipment lifecycle** — Customer POST creates **order_ups** with pending review;
  staff POST **review** updates approval, tracking number, corrections.

• **Tracking refresh** — **sync-tracking** (or refresh orchestration) calls the
  carrier API, **sorts** scan events chronologically, **de-duplicates** history rows,
  updates summary fields on the order, returns **activityPath** for the map.

• **Disruption rerouting** — **backend/lib/disruption-router.ts** (or equivalent) builds a
  hub graph, marks blocked edges, runs **Dijkstra** for a **minimum-cost** alternate
  path; result is shown on the operations map (in-memory graph; not necessarily
  stored as edge tables in the ERD).
